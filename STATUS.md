**Of the 13 failures, 6 are the missing ledger field, not the agent.** MT-S03 and
MT-A02 ask about the savings club, and the brief never contained the benefits. They
are counted separately from model failures rather than folded into the total.

The remaining failures are real rather than grader artefacts, and they cluster on
one behaviour: **the agent declines to answer questions about the savings club.**

**That is not a model failure.** The site
publishes "annual membership includes a yearly cleaning and inspection, waived
dispatch fees, priority scheduling, 15% off repairs, and 5% off new equipment."
The brief contains only `Budget Savings Club Membership $250 per year` — a price
line with no benefits — and the ledger has no field for them. The agent was never
told, so saying it does not know is correct behaviour.

The failure is in the authoring: **a fact the business publishes was left out of
the ledger, and the agent was then marked down for not knowing it.** The scenario
grader asked for benefits that were never supplied. This is the same class of
mistake as the placeholder guard and the price check — a test that measures the
brief rather than the agent — and it was only caught because the reply was read.

**But the same question exposes a real platform finding**, which is separate and
is written up in `FINDING-club-knowledge.md`: an earlier build from the same brief
answers the membership question with the site's wording, and this rebuild declines.
The brief contained the benefits in neither case. Two builds, same brief, different
knowledge — the cause is unknown and the note does not guess at it.

The first run produced nothing usable and was cleared. Two causes, both fixed:

- **Reply extraction used a character offset.** The page re-renders between turns
  and its total length can shrink, so `after.slice(before)` returned an empty
  string for turns 2 and 3 in 22 of 29 records. It now takes everything after the
  last occurrence of what the customer just said.
- **The account quota was hit mid-run**, so the remaining replies are the quota
  message. The runner now stops on the first quota reply instead of recording it.

**Sealed validation set.** Not built, and the design changed after a measurement.

The plan was fresh replies on the same 55 scenarios. Measured with
`BAAI/bge-small-en-v1.5`, two trials of the same scenario have a **median cosine
similarity of 0.940**, with 23 of 55 pairs above 0.95 — the agent is templated, so
"fresh replies" would be about 42% near-duplicate of the corpus the graders were
fitted to, before any label was collected.

The revised design is in `datasets/CLEANING-PROTOCOL.md`: someone other than the
grader author writes 20 new scenarios, the author writes graders for them from the
spec before any reply exists, and the set is labelled blind and scored once.
`datasets/clean_sealed.py` does the exclusions and the contamination check
deterministically; `datasets/measure_similarity.py` reproduces the number above.

## What to check before believing the A5 result

- **The scheduling lane.** A2 lost 3 scenarios there against A0. If A5 recovers
  them, the after-hours rule is a clean win. If it loses more, the rule is
  competing with the hours rules the same way A1 and A3 did.
- **The emergency lane.** A5's whole point. It should be 8/8, not 6/8.
- **The integrity gate.** It must stay at 0/53. A gate failure is not a score.
- **Whether the quota message leaked into any transcript.** Any reply containing
  "cannot continue right now" is a harness artifact and must be dropped before
  scoring, not counted as an agent failure.
